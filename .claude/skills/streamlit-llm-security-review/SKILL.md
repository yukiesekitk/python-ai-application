# Streamlit + LLMアプリ セキュリティレビュー

## このスキルについて

Streamlit製のLLM活用アプリは、DBや認証を持たない個人用ツールであっても独自のリスクプロファイルを持つ。一般的なWebアプリのセキュリティチェックリスト（SQLインジェクションやセッション管理の脆弱性など）をそのまま当てはめても的外れになりやすい。代わりに、次の3つの性質から来るリスクに焦点を当てる。

1. **LLM APIキーという「取り扱い注意」な秘密情報を扱っている**（コード・ログ・エラーメッセージへの混入、複数ユーザー間での共有）
2. **ユーザー入力がそのままLLMへの指示や表示コンテンツになる**（プロンプトインジェクション、LLM出力の無条件レンダリング）
3. **Streamlitの実行モデル特有の落とし穴がある**（`st.cache_resource`によるプロセス全体共有、`unsafe_allow_html`）

DBがない・認証がないこと自体は「チェック漏れ」ではなく意図的な設計であることが多いので、それを問題点として指摘しないよう注意する。

## レビューの進め方

1. **スコープを把握する。** エントリーポイント（`app.py`など）、LLMクライアントのラッパー、各機能/ページモジュール、設定・シークレットの扱い方（`.env`, `st.secrets`, 環境変数, サイドバー入力など）、依存関係定義（`requirements.txt` / `pyproject.toml`）を特定する。プロジェクトにCLAUDE.mdなどのドキュメントがあれば、意図的な設計判断（例: 「APIキーはあえて永続化しない」）を先に読み、それを踏まえてレビューする。
2. **`references/checklist.md`の各カテゴリを順に確認する。** 各カテゴリには具体的なgrepパターンや危険なコード例・安全なコード例が載っている。実際にコードを検索し、該当箇所があれば行番号付きで記録する。
3. **見つけた指摘を重要度別に整理し、下記のレポート形式でMarkdownとして出力する。**
4. **良好な設計判断も明記する。** 何がすでに安全に扱われているかを示すことで、レポートが重箱の隅をつつくだけのものではなく、本当にリスクがある箇所を伝えるものになる。

## 重要度の目安

- **Critical**: 第三者がAPIキーや機密情報を直接取得できる、または任意コード実行につながる
- **High**: 悪意あるユーザー入力によってコスト濫用・情報漏洩・意図しないLLM出力の実行/表示が起きうる
- **Medium**: 特定条件下でのみ悪用可能、または影響範囲が限定的
- **Low**: 実害は小さいがベストプラクティスから外れている
- **Info**: 指摘というより気づき・提案

## レポート形式

必ず次のテンプレートに沿ってMarkdownで出力する。指摘がないカテゴリは省略してよいが、「良好な点」セクションは必ず書く。

```markdown
# セキュリティレビュー: <アプリ名/対象>

実施日: <YYYY-MM-DD>
対象: <レビューしたファイル/ディレクトリ/コミット範囲>

## 総合評価
<全体的なリスクレベルと、最も優先して対応すべき点を1〜3文で>

## 指摘事項

### [Critical] <タイトル>
- 該当箇所: `path/to/file.py:123`
- 内容: <何が問題か>
- 想定される影響: <悪用された場合に何が起きるか、具体的なシナリオで>
- 推奨対応: <どう直すか>

### [High] <タイトル>
...

(以下、重要度が高い順に並べる。同一カテゴリ内の複数指摘は連番でよい)

## 良好な点
- <すでに安全に設計・実装されている点を具体的に>

## 参考
- <該当する場合、参照した外部情報やチェックリストの節など>
```

## 注意点

- **推測で「危険」と断定しない。** 例えば`unsafe_allow_html=True`があっても、渡している内容が完全に静的な文字列（ユーザー入力もLLM出力も混じらない）ならXSSにはならない。実際にデータの流れを追い、外部/ユーザー由来の値が到達するかを確認してから重要度を判断する。
- **LLMプロバイダに依存する実装詳細は、実際のコードに合わせて読み替える。** チェックリストはGemini/OpenAI/AnthropicいずれのSaas型LLM APIにも共通する観点で書いてあるが、SDKごとにAPI呼び出し方法や設定パラメータ名は異なるので、対象アプリで実際に使われているSDK/呼び出し方を確認してから当てはめる。
- **公開範囲を確認する。** ローカルでしか動かさない個人用ツールと、社内外に公開するStreamlitアプリでは、同じ実装でもリスクの深刻度が変わる（特に「セッション状態/マルチユーザーでのデータ混在」カテゴリ）。レビュー対象がどちらか不明な場合はユーザーに確認する。
